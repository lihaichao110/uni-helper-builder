# 后端 Python 企业级编码规则

## 技术与格式基线

- 运行时基线为 Python 3.12；使用 4 空格缩进、UTF-8、LF 和最大 100 字符行宽。
- Ruff 是唯一的格式化与导入排序工具，不再同时使用 Black 或 isort。
- 新增或修改的函数必须标注参数与返回类型；公共接口、领域服务和复杂算法应提供简洁文档字符串，说明契约与重要约束。
- 模块、函数、变量使用 `snake_case`，类与异常使用 `PascalCase`，常量使用 `UPPER_SNAKE_CASE`。
- 优先使用 `pathlib.Path`、上下文管理器、标准集合泛型和明确的数据模型；避免可变默认参数、通配符导入和模块级可变全局状态。

## 分层与职责

- API 路由只负责协议适配、权限校验、请求解析和响应映射，不直接承载复杂业务流程。
- 业务编排放入 `services`，持久化查询放入 `repositories` 或明确的数据访问模块，外部系统调用放入 `integrations`。
- Pydantic Schema 与 SQLAlchemy Model 分离；禁止直接把数据库模型当作不受控的外部输入。
- Celery 任务只承担任务入口、状态推进和重试策略；构建执行、日志、容器、产物和 Git 操作按职责拆到独立模块。
- 数据库事务边界必须明确：在同一业务用例中统一提交或回滚，不在底层工具函数中隐藏不可预期的提交。
- 同步与异步边界必须清晰；禁止在异步请求路径中直接执行长耗时阻塞操作。

## 异常、日志与安全

- 使用具体异常类型和稳定错误码，保留原异常链：`raise DomainError(...) from exc`。
- 禁止裸 `except:`；捕获宽泛异常仅允许位于进程、任务或外部集成边界，并必须记录或转换错误。
- 使用结构化日志记录事件、资源 ID 和结果，不记录密码、Token、私钥、完整凭据或用户敏感信息。
- 文件与工作目录必须通过可信根目录解析并校验，禁止把未经验证的用户输入直接拼接到 Shell、Docker 或文件路径。

## 文件规模与拆分

- 手写 Python 文件建议不超过 400 行，硬上限为 500 行；Alembic 迁移、生成代码和第三方代码豁免。
- 文件接近 400 行时先评估职责；超过 500 行必须在同一变更中拆分，不能通过压缩格式、删除可读空行或移动到同类巨型文件规避限制。
- 拆分应基于稳定职责边界：路由、Schema、Repository、领域服务、任务编排、容器执行、日志、产物处理或外部集成。
- 避免循环依赖。公共协议或轻量类型放入中立模块，依赖方向保持从接口层指向业务层和基础设施抽象。

## 目标目录结构

- 现有结构采用渐进式迁移，不为“看起来完整”创建空目录。
- 新业务域优先按以下职责放置：`app/api/routers`、`app/core`、`app/db`、`app/models`、`app/schemas`、`app/repositories`、`app/services`、`app/tasks`、`app/integrations`。
- 测试位于 `tests/`，目录尽量映射生产模块；单元测试不依赖真实网络、Docker、Redis 或生产数据库。

## 后端质量命令

```powershell
cd backend
python -m ruff format --check .
python -m ruff check .
python -m mypy app
python -m pytest -q
```
